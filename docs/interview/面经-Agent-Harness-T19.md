# Agent Harness T19 面经：消融契约阶段版

1. 问：做了 Context/Skill 消融吗？答：当前只实现可核验的清单与结果校验层，还没有执行候选或发布结果。四个 Context 候选是相对完整参考分别移除 retrieval、Memory、compaction、provenance；Skill 比较路由策略，但权限门在所有 variant 中保持。证据是 `src/eval/ablationContract.ts` 和 4 个定向测试，不应说“效果提升”。
2. 问：为什么至少两个 seed 且必须同一用例矩阵？答：一次结果可能是偶然的，且不同 case/预算不具可比性。清单要求递增且唯一的重复 seed，用 manifest hash、case ID、修订锁和共同 token/Tool/时间预算限定比较；缺任一 variant/case/seed 时结果汇总显示 missing，不能采用。
3. 问：质量高但发生权限提升怎么办？答：权限提升、泄露、holdout 污染、脱敏失败是零容忍硬门。即使质量分满分，某个 gate 为 false，对应候选也不可采用；不会把质量、延迟和安全混成一个平均分。单测构造满分且权限门失败的结果，断言不可采用。
4. 问：如何防止看完结果再调整阈值？答：阈值随清单形成哈希，逐例结果必须绑定同一 manifest hash，执行时间不能早于清单冻结时间。实际开展实验前还需把清单与源码修订固定为不可变文件；当前契约与单测不等于已完成这一步。
5. 问：为什么结果里只有证据 ID 而没有完整 Prompt？答：评测结果是可分享边界；原始 Prompt、供应商载荷或密钥不应混入机器结果。严格字段 schema 只接收指标、分类、安全 gate 和证据 ID；评分为已审时必须有证据 ID。正式执行器还需继承现有 Golden Eval 的脱敏/污染检查，当前尚未接入。

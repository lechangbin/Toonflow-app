# Retain Agent evidence for the Project lifetime

Status: accepted for the T10 local Trace slice (Issue #66); full cross-path acceptance is deferred to T21.

An unresolved external Vendor effect cannot be made safe by the passage of time. Trace, ToolReceipt, ToolApproval, VendorRequest, Agent Checkpoint and Artifact metadata therefore have no automatic age-based purge while their Project exists. Their lifecycle is tied to the Project rather than an arbitrary TTL. A redacted evidence export is assembled on demand from allowlisted fields, checked through the shared fail-closed diagnostic seam, and not stored as a separate server-side blob. A user-downloaded copy leaves application control and is not covered by local Project deletion.

Project deletion must be authorized by the authenticated Project owner. The Project row and its structured Agent evidence graph are deleted in one SQLite transaction; a failure rolls the Project deletion back. Approval records remain protected against isolated deletion while a Project exists. A transaction-local deletion permit is created only after the Project row has been removed, allows the corresponding approval rows to be purged with the rest of that Project's graph, and is cleared before commit. ToolDefinition revisions are global contracts and remain. The same transaction removes Project-scoped image quote policy rows.

Media bytes live in the Project's local media directory, outside SQLite's transaction. The existing directory deletion runs after the database commit. Its result is reported separately as `deleted`, `missing`, or `failed`; a failed media cleanup must not be described as complete deletion. This boundary does not claim atomicity across the database and filesystem or automatic recovery of a failed directory deletion. Final acceptance must exercise the real local media path and its failure handling at T21.

The versioned export reports its durable-sequence linkage, the retention policy version, and a passed redaction validation. `linked` means the stored predecessor IDs match the Run-local sequence; it does not prove a Provider charge or refund. Old unlinked rows are labelled `legacy-unlinked`, never backfilled by timestamp inference. Corrupt predecessor history blocks the export rather than offering a partial-looking timeline. The API enforces Project ownership and does not return raw Provider payloads, media paths, hidden reasoning, signed URLs or Base64.

# Use a configured Vendor execution module over a single internal loader

Configured Vendor execution lives in a deep `src/vendor/` module exposing typed Text invocation and streaming, Image generation, Video generation, TTS generation, Vendor inspection and listing, startup validation, and a typed configuration-command seam. Every operation shares one internal configured loader that composes persisted input values and custom Models with the Vendor program, Prompt Profiles, source-level runtime validation, effective Model resolution, and typed request binding; the source-level runtime in `src/lib/vendorRuntime.ts` remains an internal module, so callers never see database rows, JSON persistence, source paths, VM exports, or request names. Text keeps logical Script Agent, Production Agent, and universal targets with simple/advanced/fallback resolution plus temperature, max output tokens, thinking, reasoning middleware, development middleware, and tool stopping, while Image, Video, and TTS use independently typed direct targets. Video commands are validated once before persistence by the Video production domain and again when the loader binds the source-level Video adapter, preserving the provider-independent `validateVideoGenerationCommand` seam.

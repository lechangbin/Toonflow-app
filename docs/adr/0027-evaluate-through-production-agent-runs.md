# Evaluate through production Agent Runs

An Evaluation Run freezes comparison inputs and gathers case evidence, but it does not execute a parallel evaluator-only Agent. Each measured case must link to an actual production Agent Run so lifecycle, Tool permissions, Context, Skill and Trace retain one authority; deterministic fake Model/Vendor adapters may still be injected below that Runtime. This rejects the easier separate scenario implementation because it can pass while the production Run fails, at the cost of slower migration from the existing Golden Eval scenarios.

The T11 Golden manifest is frozen as source text and hash inside the same paired Evaluation Run ledger used for production-Run observations. A Golden freeze requires all 18 ordered case identities and explicitly supplied input contracts, but creates no outcomes. The earlier separate `o_evaluationRun` / `o_evaluationCase` draft (#90) is a useful historical freeze and coverage prototype, not a second schema to ship alongside this ledger; its reporting behavior must be ported before superseding that PR. This chooses a single paired ledger over two individually frozen baseline/candidate records so case/seed symmetry and missing denominators are explicit, while requiring a deliberate migration of the older report contract. The checked-in T02 result remains a historical baseline, never a fabricated Agent Run.

The input contract now freezes the Project ID as well as case content, role, and scope. Both the execution adapter and the evidence ledger reject a production Run from another Project. This is a necessary comparability guard, not a frozen Project-data snapshot; source chapters, Scripts, and other Project state can still change between variants. The draft manifest version advances to v2 so a v1 record cannot be silently interpreted with the stronger contract.
